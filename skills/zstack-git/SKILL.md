# zstack git policy

The run's policy (`$Z status` shows `git`, `worktree`, `deploy`) comes only from what the user said. The defaults are `no-commit`, `off` and `never`. Policy can only be raised by an explicit user message, never by an agent.

| policy | allowed |
|---|---|
| `no-commit` | read-only git (`status`, `diff`, `log`, `blame`). No `add`, `commit`, `stash`, `checkout -- file`, `reset`, `rebase`. |
| `commit` | the manager, or one designated worker, commits **this run's changes only**. No push. |
| `commit-push` | as above, plus a plain `git push` to the current branch. No force push, rebase or amend unless the user asked. |

Always:
- Only the manager, or the agent it names, runs git write commands. Workers never commit on their own.
- Stage explicit paths (`git add path1 path2`), never `git add -A`, unless the user said "commit all". Check `git status` first. Unrelated dirty or staged files belong to the user: leave them and mention them.
- Small commits, one concern each, `type(scope): summary` (feat, fix, refactor, perf, test, chore, docs). No co-author or "generated by" trailer.
- Never stage docs, plans, specs, ADR drafts, handover notes, `flake.nix`/`flake.lock` edits the user didn't ask for, or anything under the zstack run dir.
- Stay on the current branch. If the user said "push to main/master directly", do that and don't create a branch.
- Worktrees only with `--worktree per-writer`: one per parallel writer under `<repo>/.worktree/<task>`, merged back by the manager. After the user says the PR is merged, remove the worktrees and local branches.
- PRs, tags and version bumps only on explicit request. Bump the version (e.g. `Cargo.toml`) before tagging.
- Before any commit, scan the staged diff for secrets: `git diff --staged | grep -nEi '(api[_-]?key|secret|token|password|BEGIN .*PRIVATE KEY|ghp_|xox[bp]-)'`. Any hit stops the commit.
- If the user is editing or building ("don't run git", "I'm deploying manually"), no git commands at all, including read-only ones.
